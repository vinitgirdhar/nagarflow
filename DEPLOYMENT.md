# Deployment runbook

Local development and verification are described in README.md. For the full Render deployment, use [RENDER.md](RENDER.md) and the root `render.yaml` Blueprint. Repository configuration alone does not create a live service.

For a Netlify frontend, follow [NETLIFY.md](NETLIFY.md). Keep the persistent Render service for the API, worker, databases, media and MFA key. Configure the real backend HTTPS origin at Netlify build time and allow the exact Netlify production origin in Render; verify secure sessions and CSRF through the deployed proxy before launch.

1. Install with `bash scripts/setup_cloud.sh`. Provision the initial administrator privately using `venv/bin/python scripts/manage_users.py create --email YOUR_ADDRESS --name YOUR_NAME`; finish password change and MFA at first sign-in.
2. Set absolute persistent `NAGARFLOW_AUTH_DB`, `NAGARFLOW_DB_PATH` and `NAGARFLOW_TENANT_DATA_DIR` paths; run `venv/bin/python scripts/prepare_dev.py` with these same settings. Preserve uploads and the control database `.mfa-key` file. Do not seed synthetic records into production.
3. Set exact HTTPS `NAGARFLOW_TRUSTED_ORIGINS`, backend URL for the Next server, and production environment. Run `venv/bin/python scripts/preflight.py --production`. Review warnings, including enrollment. Secure cookies are mandatory in production.
4. Build with `cd nagarflow-next && npm run build`. Supervise separate `scripts/start_production.sh api`, `worker` and `web` processes. Reverse proxy HTTPS to the web service; keep API private. Configure service restart, persistent logs, request limits and monitoring on the actual host. The scripts do not configure hosting or TLS.
5. Configure provider credentials privately and a trusted gateway implementing the versioned signed intake protocol in OPERATIONS.md. Validate native signatures before forwarding. Permit only necessary provider domains; local core flows do not require paid models. Weather is optional, explicitly polled for each municipality's real coordinates. External map assets need allowed networking; core controls have fallbacks.
6. Stop API and worker writes for a coordinated backup: `venv/bin/python scripts/backup.py create --output /NEW_PRIVATE_DIRECTORY`. Restore using `restore --source /BACKUP --destination /NEW_RESTORE_DIRECTORY`. Restore never overwrites live stores and revokes restored sessions. Validate a restore on the deployment host before launch. Store backups encrypted with restricted access and a defined retention policy.
7. Run backend and browser checks, then actual provider-delivery, HTTPS/cookie, restart and restore checks. Commit `62d102d` passed the full GitHub workflow; see [successful GitHub Actions run](https://github.com/vinitgirdhar/nagarflow/actions/runs/39030290654). CI does not validate your actual provider configuration, HTTPS host or production restore procedure.

No provider values are included in source. GROQ_API_KEY, SARVAM_API_KEY and TELEGRAM_BOT_TOKEN are optional external integrations; NAGARFLOW_WEBHOOK_SECRET is a private raw process secret shared only with the trusted gateway.
